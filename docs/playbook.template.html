chatop: a harness for copy-and-paste development

No coding agent, just a chat window. chatop keeps the project memory in your repo and builds each packet you paste, with code context found by codegraph. It applies the LLM's one-block reply atomically, proves TDD red then green, runs your checks and commits. Then the next packet is already on your clipboard.

1 · PasteThe packet is already on your clipboard. Paste it into Claude, ChatGPT or Gemini.
2 · LLM repliesOne ````chatop block with tests, code, docs, questions and context requests.
3 · CopyClick the copy button on that block. chatop watch sees it.
4 · ApplyValidate paths and edits in memory, then write atomically, or put a repair prompt on the clipboard.
5 · VerifyTests alone must fail, then with the code all checks must pass. Commit the slice.
6 · Next packetEvidence, state and codegraph context assembled and copied. Back to 1.

Turn economics

A turn is one copy into the chat and one copy back. That is the only cost a human feels, so every design choice either removes a turn or removes thinking from a turn.

Waste in plain chat developmentchatop techniqueEffect
Re-explaining the project in every new chatSelf-contained packets; repo-as-memory (.chatop/state.json, docs/)A fresh chat per phase costs nothing
"Paste me file X" round-tripsSlices declare touches; codegraph pre-loads files, symbols, callers and affected testsThe context is there on the first try
Serial questions@@ask batches with recommended options pre-checked; chatop acceptOne decision round instead of many
Hand-applying code; partial appliesOne envelope; SEARCH/REPLACE edits; atomic, validated applyZero manual edits; never half-applied
A separate "red" turn for TDDTwo-stage apply: tests first must fail, then the code must passVerified TDD in one turn
Copying error logs by handFailing check output goes into the next packet automaticallyRetries need no human analysis
Vague "that didn't work" retriesPrecise repair prompts (stale turn, missing SEARCH, protected path, truncation)The fix-up costs one paste

What chatop sees

Prompts

These are the exact templates chatop assembles into packets (src/chatop/prompts/). Every packet is system + the phase prompt + contract + state + human input + evidence + docs + code context + repo map, cut to the token budget by priority. $name placeholders are filled per turn. You don't paste these by hand; chatop does. They're shown so you can audit and tune them.
