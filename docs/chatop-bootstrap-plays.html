From an empty folder to continuous development, with chat only

You will rebuild chatop (the app that relays packets and replies between you and chat LLMs) using nothing but chat windows, a terminal and a clipboard. No coding agent, no harness. Code search is the codegraph CLI.

  1. Stage 0, the kernel. One standard-library script, relay.py, builds packets and applies replies with red/green TDD and a commit. It is proven by 9 black-box checks, so you trust it before any chat touches your repo.
  2. Stage 1, the core. Eleven slices from a plan, in five waves. Slices of a wave share no files, so several chats work at once; you apply their replies in any order. The oracle is accept.py, which replays five labs through the chatop command line.
  3. Stage 2, self-hosting. chatop adopts its own repo and builds its web UI and TUI with its own parallel relay. From then on the kernel is a rescue tool.

Part I is the product itself: the PRD, the design and the architecture, with the behavior contract, the decisions and the UX. They are written for coding agents as much as for people: stable requirement ids, a traceability table, an integration guide for existing products, and a one-command extractor that turns this page back into markdown files. Use them to implement the product, or to incorporate it into one you already have.

Seeded (default) uses the verified kernel and the design documents from the kit. Purist has chats write those too; the later plays are identical. Use the switch above; your progress is kept in this browser.
